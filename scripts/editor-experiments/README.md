# Editor experiments for ADR-2467-01

**Not production code.** These scripts back the *Experiments* section of
[ADR-2467-01](../../doc/architecture/adr/ADR-2467-01-select-future-rich-text-editor-strategy.md).
Nothing in the application imports them, they are not part of any test suite or CI job,
and the packages they need are **not** dependencies of eXeLearning. Each folder has its own
`package.json` only to pin the exact versions that were measured; install them in a
temporary copy, never in this checkout.

| Folder | What it measures |
|---|---|
| `html-roundtrip/` | Load/save fidelity of candidate editors on every HTML fragment of the `.elp`/`.elpx` fixtures in `test/fixtures` |
| `asset-uri/` | Whether `asset://` URLs survive display, editing, paste, dialogs and reload in TinyMCE 8, HugeRTE and ProseKit, and which hooks each editor needs |

## How to run

Requirements: Node 22 or later, npm, Bun (for the Tiptap bundle), `python3` (static server of
`asset-uri/run.mjs`) and a Chromium that Playwright can launch
(`npx playwright install chromium` in the temporary copy if none is cached).

```sh
EXE="$PWD"                                   # this checkout, only read
TMP="$(mktemp -d)"
cp -R scripts/editor-experiments/. "$TMP"

# 1. HTML round trip (about 40 s)
cd "$TMP/html-roundtrip"
npm install                                  # exact devDependencies from package.json
node metrics.mjs                             # self-check of the normalisation
node extract-corpus.mjs "$EXE" corpus.json   # -> corpus.json
bun build tiptap-entry.mjs --outfile tiptap.bundle.js --minify
node roundtrip.mjs "$EXE" all corpus.json    # -> results.json, results.md

# 2. asset:// experiment (about 10 s)
cd "$TMP/asset-uri"
npm install
npx esbuild harness-prosekit.js --bundle --format=iife --outfile=harness-prosekit.bundle.js
node run.mjs                                 # all editors, all hooks
node run.mjs --net                           # with an eXe-style regex safety net at GetContent
node run.mjs tinymce hugerte --off=2         # ablation: switch hook 2 off (1..7, or "1,5")
node run.mjs prosekit --off=3                # ProseKit hooks 1..4
```

`roundtrip.mjs` serves eXe's vendored TinyMCE 5.10.2 read-only from
`$EXE/public/libs/tinymce_5/js/tinymce` (with eXe's `exemedia` plugin); every other editor
comes from the temporary `node_modules`. `run.mjs` starts `python3 -m http.server` on port 8765.

## Reproducibility

- `extract-corpus.mjs` is deterministic: at `f64d72fb5` it produces 1,319 fragments and a
  `corpus.json` with SHA-1 `61ee50b9f4b2b6eeb07ee1bc324a1a24416fadac`. The file is about
  8 MB, so it is regenerated rather than committed. Its content comes only from
  `test/fixtures`.
- Two full runs of `roundtrip.mjs` produced identical `results.md` apart from the timestamp
  line; two runs of `run.mjs` produced the same pass counts.
- The numbers quoted in the ADR are from Chromium 145.0.7632.6 (Playwright 1.58.2) for the
  round trip and Playwright 1.63.0 for the `asset://` run, on 2026-09-27.

## Limits (read before quoting a number)

- **One API load and save per fragment** (`setContent` then `getContent`, or the editor's
  equivalent). No typing, undo, paste or drag and drop in `html-roundtrip`; one browser
  (Chromium), one run.
- **Configurations are asymmetric.** The TinyMCE family gets eXe's permissive parsing options
  (`valid_elements: '*[*]'`, `schema: 'html5'`, `convert_urls: false`, ...) and core plugins
  only (`lists advlist link image media table code`; `exemedia` instead of `media` on 5.x).
  Tiptap gets StarterKit, an inline Image and generic `class/style/id/title/lang/dir`, without
  the preserve layer described in the ADR, so it cannot keep `data-*` by construction.
  wangEditor-next is stock. Squire runs with no DOMPurify, which is more permissive than a
  real deployment.
- **eXe's own plugins are not loaded** (about 40 in production), nor its `asset://` to
  `blob:` hooks in `html-roundtrip`.
- **The metrics count losses.** Only the "identical" column sees additions such as
  `sandbox=""` on iframes, `object`/`embed` turned into iframes, `rel` on links or `<p>`
  wrappers. A kept `iframe` or `asset://` URL does not mean the content still works.
- **The corpus is not a sample of user projects.** It is 30 test fixtures, deduplicated (so
  frequency is lost); 55 % of the fragments are `contentv3.xml` legacy fields, and some
  `htmlView`/`jsonField` HTML is generated by iDevice code rather than typed in the editor.
  Asset paths are rewritten to `asset://<hash>.<ext>`, an approximation of the importer's
  random UUIDs.
- **`asset-uri` covers six elements** with a synchronous in-memory asset cache and the stock
  image dialog. Not covered: asynchronous or peer resolution, `span.mce-preview-object`,
  `resolveHtmlWithAssets`, eXe's `exeimage`/`exemedia` dialogs, drag and drop, Firefox and
  WebKit, Squire and wangEditor-next.

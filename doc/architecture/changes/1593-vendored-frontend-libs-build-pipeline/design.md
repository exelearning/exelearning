# Vendored frontend libraries sourced from npm and generated at build time — design

## Summary

The frontend's third-party JavaScript and CSS used to ship as pre-minified blobs
committed under `public/`. This design replaces those blobs with npm-declared
dependencies plus a deterministic build step (`bundle:vendor`) that regenerates
the runtime files from `node_modules/`. It covers three pieces implemented in
PR #1593: a copy step for library distributions (`scripts/copy-vendor-libs.js`),
an esbuild-based generator for the browser Yjs runtime
(`scripts/build-yjs-shims.js`), and a Dependabot configuration that keeps the
now npm-managed dependencies current (`.github/dependabot.yml`). The result is
explicit provenance, a real security-update path, and a single source of truth
for libraries that were previously duplicated across the tree, with the served
assets still coming from the app's own origin (no CDN).

## Problem statement

Maintainers and reviewers cannot audit or safely update opaque, committed vendor
blobs: they carry no version metadata, several are duplicated byte-for-byte
across iDevice export directories, and updating one means hand-editing minified
files. There is no automated security-update path, and the vendored code inflates
the repository with tens of thousands of unreviewable lines. At the same time,
the app must keep serving these assets from its own origin for offline, Electron
desktop, static, and embedded/opaque deployments — a runtime CDN is not an option.

## Goals

- Declare every regenerated frontend library in `package.json`, pinned by
  `bun.lock`.
- Generate the runtime files under `public/` from `node_modules/` in a single,
  order-safe `bundle:vendor` step; gitignore the generated outputs.
- Guarantee the browser shares one Yjs instance while preserving the existing
  vanilla global-script loader contract.
- Fail the build loudly if the vendor step is skipped or runs out of order.
- Establish automated, grouped dependency updates.
- Keep assets served from the app's own origin (no CDN) across web, desktop,
  static, and embedded builds.

## Non-goals

- Migrating MathJax (`public/app/common/exe_math/`) off its committed subset —
  explicitly deferred.
- Rewriting the vanilla frontend to import libraries as ESM through an
  application bundler (globals are retained).
- Adding subresource-integrity/checksum verification of the copied files beyond
  the lockfile — noted as future work.
- Replacing the hand-written IndexedDB persistence with an npm `y-indexeddb`
  build — noted as future work.

## Current state

Before this change the runtime files were tracked minified blobs. PR #1593
removes them (roughly 56,900 deleted lines across the vendor artifacts) and,
after this change, they are generated:

- Library distributions are copied by `scripts/copy-vendor-libs.js` (its `COPIES`
  table lists every `node_modules` → `public/` mapping).
- The Yjs runtime is generated by `scripts/build-yjs-shims.js` from the root
  `yjs` / `y-websocket` packages, with a hand-written IndexedDB persistence.
- Both are invoked by the `bundle:vendor` npm script, wired into `build:all`
  before the parallel `bundle:resources` step (`package.json`).
- Generated destinations are gitignored (`.gitignore`); the Yjs shim *sources*
  under `public/libs/yjs/build/` stay tracked.
- The consumers are unchanged vanilla code: `public/app/yjs/yjs-loader.js` loads
  the generated Yjs scripts and reads `window.Y` / `window.WebsocketProvider` /
  `window.IndexeddbPersistence` (see `public/app/yjs/YjsDocumentManager.js`).

The operational architecture these files feed into is documented separately and
is not restated here — see `doc/architecture.md`, `doc/development/real-time.md`,
and `AGENTS.md` (the "Client is Source of Truth" and export/serving rules).

## Proposed design

`bundle:vendor` runs two generators in sequence:

```
package.json / bun.lock        node_modules/
        │                           │
        ▼                           ▼
  bun install ────────────────► node_modules populated
                                    │
        ┌───────────────────────────┴───────────────────────────┐
        ▼                                                         ▼
scripts/build-yjs-shims.js (esbuild)              scripts/copy-vendor-libs.js
  yjs.min.js         (IIFE → window.Y)              COPIES: node_modules/**/dist
  y-websocket.min.js (alias yjs→window.Y)            → public/libs/**, public/app/**,
  y-indexeddb.min.js (minify hand-written IIFE)        public/files/perm/idevices/**/export/**
        │                                                         │
        └──────────────────────► public/ (gitignored) ◄──────────┘
                                    │
                                    ▼
                         scripts/build-resource-bundles.js
                    (BASE_LIBS required:true → throws if missing)
                                    │
                                    ▼
                         public/bundles/libs.zip, …
```

Ordering matters: `bundle:vendor` must complete before `bundle:resources`, which
packages `public/libs/` into `libs.zip`. To make a skipped/mis-ordered vendor
step a hard error, `build-resource-bundles.js` marks the critical vendor files as
`required` and throws when they are absent.

## User experience

No end-user-visible change. The app loads the same libraries at runtime and
behaves identically. The change is visible to contributors and CI:

- A fresh checkout has no runtime vendor files until `bundle:vendor` (via
  `make bundle` / `build:all`) runs.
- Editing a generated file has no effect — the source of truth is the npm package
  version (documented in the header of `scripts/copy-vendor-libs.js` and in
  `.gitignore`).
- If the vendor step is skipped, the build fails with
  `Missing required library '…'. Run 'bun run bundle:vendor' before 'bundle:resources'.`

## Technical design

### Copy step — `scripts/copy-vendor-libs.js`

A CommonJS script exporting `COPIES`, `copyFile`, `resetCreatedDirs`, and `run`
(for unit testing) and running `run()` only when invoked directly. `COPIES` maps
each source in `node_modules/` to its `public/` destination. `copyFile` creates
each destination directory once (via a `createdDirs` cache) and throws
`could not copy <src>: …` on failure, which the CLI wrapper turns into a non-zero
exit. Duplicated libraries are expressed as multiple `COPIES` entries from one
source: `html2canvas` → `progress-report`, `checklist`, `rubric` export dirs;
`simple-lightbox.min.{js,css}` → `public/libs/simplelightbox/dist/` and the
`image-gallery` export dir; `dompurify/purify.min.js` → `edicuatex` and
`public/libs/dompurify/`. MathJax is intentionally excluded (documented in the
file header).

### Yjs shim generator — `scripts/build-yjs-shims.js` (see ADR-1593-02)

Uses `esbuild` `buildSync` to emit three files under `public/libs/yjs/`:

- `yjs.min.js`: IIFE from inline `stdin`
  (`const Y = require('yjs'); window.Y = Y;`) — bundles `yjs` from root
  `node_modules` and publishes `window.Y`.
- `y-websocket.min.js`: bundles `public/libs/yjs/build/y-websocket-entry.js` with
  `alias: { yjs: …/build/yjs-global-shim.js }`, so `WebsocketProvider` reuses
  `window.Y` (one Yjs instance).
- `y-indexeddb.min.js`: minifies the hand-written IIFE
  `public/libs/yjs/build/y-indexeddb-browser.js` (`bundle: false`), which reads
  `window.Y` and publishes `window.IndexeddbPersistence`.

### Build enforcement — `scripts/build-resource-bundles.js`

`BASE_LIBS` marks the gitignored jQuery/Bootstrap files as `required: true`.
`buildLibsBundle()` throws `Missing required library …` when a required file is
absent, while repository-tracked sources (`common.js`, `favicon.ico`) only warn —
matching the previous lenient behavior for tracked files.

### Wiring — `package.json`, CI, E2E

`"bundle:vendor": "bun scripts/build-yjs-shims.js && bun scripts/copy-vendor-libs.js"`
runs inside `build:all` before `bundle:resources`. `.github/workflows/ci.yml`
adds a "Build vendor libs" step before unit tests. `.github/workflows/e2e.yml`
adds `public/libs/**`, the mermaid and edicuatex/DOMPurify outputs, and the
html2canvas / SimpleLightbox iDevice-export files to the dynamic-bundles artifact
so E2E runs against generated assets.

## Data model

No database or Yjs-document schema changes. The "data" of this design is three
static declarative structures:

- **`COPIES`** (`scripts/copy-vendor-libs.js`) — `{ src, dest }[]`,
  `node_modules` → `public/`.
- **`BASE_LIBS`** (`scripts/build-resource-bundles.js`) —
  `{ src, dest, required? }[]`, with vendor files flagged `required: true`.
- **`.gitignore` vendored-libs block** — the authoritative list of generated
  destinations (Phase 1: libraries already in `package.json`; Phase 2: newly
  added devDependencies), with `public/app/common/exe_math/` explicitly excluded.

## Migration and compatibility

- Committed vendor blobs are deleted and their destinations gitignored; the first
  `build:all` / `make bundle` after checkout regenerates them.
- CI, packaging, and E2E paths are updated to run/consume `bundle:vendor`.
- Backward compatibility for runtime consumers is total: the same file paths and
  the same `window.*` globals are produced, so `yjs-loader.js` and the iDevice
  export scripts load exactly as before.
- Rollback is a revert of PR #1593 (restore blobs, drop the scripts and the
  `bundle:vendor` wiring).
- MathJax is deliberately left tracked, so the "no committed vendor blobs" state
  is partial until the follow-up migration.

## Security and privacy

- **Threat model.** The vendor files execute in the browser with full app
  privileges, so their provenance is security-relevant. Previously they were
  opaque committed blobs with no verifiable origin. After this change each file
  derives from a named npm package pinned in `bun.lock`, and updates flow through
  Dependabot (ADR-1593-03) rather than manual blob edits.
- **No new runtime third-party surface.** Assets are copied at build time and
  served from the app's own origin; there is no CDN fetch, consistent with the
  offline/desktop/static/embedded requirements and the opaque serving model.
- **Residual risks.**
  - Trust reduces to the npm registry plus `bun.lock` integrity; a compromised
    upstream release or lockfile could ship malicious code. There is no
    subresource-integrity or checksum assertion on the copied files beyond the
    lockfile hash (noted as future work).
  - The esbuild-generated Yjs shims and the hand-written IndexedDB persistence
    are not independently audited artifacts; a bad esbuild upgrade could change
    their output (mitigated by tests + the Dependabot build-tools group).
  - This design does not attempt to sandbox or CSP-restrict the vendored code
    beyond what the app already enforces; that remains the responsibility of the
    serving layer.
- DOMPurify remains the HTML-sanitization primitive; nothing here changes
  sanitization behavior — it only changes how DOMPurify's file is produced.

## Accessibility

No accessibility impact. No UI, markup, focus, or contrast changes; the same
libraries render the same output.

## Internationalization

No new user-facing strings. Script log/error messages
(`Missing required library …`, the Yjs load errors) are developer/CI-facing and
intentionally not translated.

## Performance

- Adds a bounded build-time step (esbuild `buildSync` for three small shims plus
  ~25 file copies); negligible relative to the full `build:all`.
- No runtime performance change: the same minified files are served, so bundle
  sizes and load behavior are unchanged.
- Repository/checkout size drops substantially (~56,900 fewer tracked lines).

## Testing strategy

- **Unit (`bun test`).** `scripts/copy-vendor-libs.spec.ts` verifies the `COPIES`
  table is non-empty, the runtime-loaded rubric `html2canvas.js` copy is present,
  all three html2canvas destinations map from the npm package, every `src`
  resolves after install, and `copyFile` throws on a missing source and creates
  each destination directory once.
  `scripts/build-resource-bundles.spec.ts` ("required vendor libs") verifies
  jQuery/Bootstrap are marked `required`, tracked sources are not, and
  `buildLibsBundle()` throws when a required file is moved aside (then restores
  it).
- **Frontend (Vitest).** `public/vitest.setup.js` loads the generated
  `libs/yjs/yjs.min.js` and exposes `window.Y` / `global.Y`, so Yjs client tests
  under `public/app/yjs/` run against the real generated shim.
- **E2E (Playwright).** Collaboration and export/static flows run against the
  vendor assets now included in the e2e dynamic-bundles artifact
  (`.github/workflows/e2e.yml`).
- **Patch coverage.** New script lines ship with the colocated `*.spec.ts`
  above, targeting the ≥ 90% patch-coverage gate in `AGENTS.md`.

## Rollout plan

Delivered as a single PR (#1593) in two conceptual phases reflected in
`.gitignore`:

1. **Phase 1** — libraries already declared in `package.json` (Yjs shims,
   pdf.js, mermaid) generated by `bundle:vendor`.
2. **Phase 2** — newly added devDependencies (jQuery, Bootstrap, showdown,
   fflate, abcjs, html2canvas, DOMPurify, interact.js, jQuery UI, SimpleLightbox,
   fabric) copied by `copy-vendor-libs.js`.

CI gains the vendor build step and E2E artifacts gain the generated files in the
same PR; Dependabot (ADR-1593-03) turns on grouped updates going forward.

## Risks and mitigations

- **Incomplete `COPIES` table** (a runtime-loaded file not listed) → build ships
  without it. Mitigated by the `required` flag for critical libs and by
  `copy-vendor-libs.spec.ts` asserting the runtime copies. Residual risk for
  non-required copies.
- **Vendor step skipped/mis-ordered** → mitigated by the `required`-throw in
  `build-resource-bundles.js` and the CI "Build vendor libs" step.
- **Upstream dist path change** → copy fails fast; the "resolves every source
  path" spec catches it after install.
- **esbuild/Yjs-ecosystem version skew** → mitigated by ADR-1593-03's grouped
  `yjs-ecosystem` and `build-tools` updates plus tests loading the real shim.
- **Supply-chain compromise** → residual; reduced to lockfile trust, no runtime
  CDN. Future SRI/checksum work.

## Open questions

- Should the copied files carry a checksum/SRI assertion in addition to the
  lockfile hash?
- Can the hand-written `y-indexeddb-browser.js` be replaced by a bundled npm
  `y-indexeddb` through the existing alias mechanism?
- What is the concrete migration path for MathJax (`exe_math/`) into this flow?
